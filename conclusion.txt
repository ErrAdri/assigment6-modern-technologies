Deploying the Recipe Sharing application to Google Cloud was very different from running it locally. What surprised me most was how much configuration happens outside the code itself. Locally, Docker Compose handled networking between the frontend and backend automatically, but in the cloud I had to pass the backend URL into the frontend at build time, set up permissions, and connect GitHub to Cloud Build. Small details, like YAML indentation or a missing API, could stop the whole build.

Cloud Run's serverless model also changed how I think about containers. With Docker Compose, my containers run continuously on my own machine and I manage them myself. Cloud Run starts container instances only when requests arrive, scales them up or down automatically, and can scale to zero when nobody is using the app, so I only pay for actual usage. Each service also gets its own public HTTPS URL.

For real-world applications, cloud deployment offers clear advantages: automatic scaling, built-in monitoring of requests and response times, continuous deployment from GitHub, and high availability without maintaining servers. Billing alerts also help control costs, which is essential for any real project.
